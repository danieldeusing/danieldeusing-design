# Migrating a surface to `@danieldeusing/design` 0.60.0

What a page, an app or a renderer must change to move from 0.59.0 to 0.60.0. `CHANGELOG.md` says
what was added and why; this file is only what breaks, what must now be written, and what a strict
Content Security Policy needs. The released `SKILL.md` and `references/*.md` are the authority for
every class named here.

## 0. Before the pin moves

- `npm view @danieldeusing/design version` answers `0.60.0`, and jsDelivr answers 200 for
  `@0.60.0/dist/danieldeusing-design.min.css`. A pin to an unpublished version 404s and the page
  renders with no CSS.
- A surface that loads single files (`tokens.css` + `chrome.css`, say) rather than the bundle checks
  the "moved" rows below: a class that changed files is gone from a page that does not load its new
  file.
- Look at the page at 1280px and 375px, in every theme, before and after. Much of 0.60.0 is a new
  look for markup that does not change (§4).

## 1. Removed — no shim

| 0.59.0 | 0.60.0 | reference |
| --- | --- | --- |
| `.filter-ctl` (a text toggle, `[aria-pressed]`) | `.switch` for on/off; `.chip-set` of `button.chip[aria-pressed]` for several at once | `filters.md`, `controls.md` |
| `.filter-set`, `.filter-set-label` (a picker marked `(•)`) | `select[data-filter]` for one of several | `filters.md` |
| `.tbl-toolbar`, `.tbl-search`, `.tbl-filter-input` | nothing to write: `initTableTools()` renders a `.filter-bar` with a `.search-field` above a `table[data-table-tools]` | `tables-and-forms.md` |
| `.dgm-btn`, `.dgm-close`, `.dgm-locked` | the zoom view is `dialog.dgm-overlay`, built by the runtime; the opener, `.dgm-zoomable`, is unchanged | `overlays.md` |
| `.toc-label` and a bare `nav` in `.toc` | `nav.navlist` with a `.navlist-label` | `chrome.md` |
| `.minimap-bar.active` | `.minimap-bar[aria-current="true"]`; `initMinimap()` returns `null` on a page with a table of contents | `runtime.md` |
| `<select data-select="off">` | no opt-out: `initSelects()` enhances every `<select>` | `tables-and-forms.md` |
| `tr[hidden]` in `base.css` | one global rule in `tokens.css`: `[hidden]:not([hidden="until-found" i]) { display: none !important }` (§4) | `foundations.md` |
| `html[data-theme=…] .dropdown-item[data-theme-value=…]` (the chosen theme in `--primary` with a glow) | the ✓ the runtime draws: call `initThemeSwitcher()`, which sets `aria-checked` (in a menu) or `aria-pressed` on the theme in force. Without the call the four items look identical | `components.md` |
| `[data-tip][data-tip-bare]` and the `.minimap-bar[data-tip]` exception | nothing: they suppressed a tooltip marker that no longer exists. A `data-tip-bare` left in markup is inert; delete it | `overlays.md` |

A page's own copy of any removed class is now a local class with the system's old name. Delete it
with the markup that uses it; do not keep it alive under the old name.

## 2. Moved to another file

Nothing to change for a surface that loads the bundle (`dist/danieldeusing-design.css`, or
`src/index.css`, or the Tailwind entry). A surface that loads files one by one adds the new one:

| what | from | to |
| --- | --- | --- |
| `.tabs`, `.tab`, `.tab--info`, `.tab-panel` | `components.css` | `data.css` |
| `dialog.dgm-overlay` and its parts | `components.css` | `overlays.css` |
| the table engine's `.tbl-*` | `components.css` | `data.css` |
| the `html.anim-off` kill switch | `components.css` | `tokens.css` |

Every new file — `icons.css`, `controls.css`, `tags.css`, `feedback.css`, `filters.css`, `data.css`,
`cards.css`, `overlays.css`, `content.css`, `utilities.css` — is exported on its own
(`@danieldeusing/design/<file>.css`) and renders on `tokens.css` alone. `utilities.css` is new, not
moved: the `.text-*` colour utilities did not exist in 0.59.0. The bundle loads it after every
component file; the Tailwind entry leaves it out, because Tailwind generates the same `text-*` names.

## 3. Markup that is now required

**A tree row's label is a `.tree-label`.** The row carries its glyph's colour; the label resets it.
Text straight in `.tree-row` renders muted (a leaf) or `--primary` (a branch).

```html
<span class="tree-row"><span class="ico" data-icon="file-code" aria-hidden="true"></span><span class="tree-label">app.ts</span></span>
```

**A labelled section of a menu is a group.** `initDropdowns()` turns a `details.dropdown` panel of
rows into an ARIA menu. A `.dropdown-label` heads a `role="group"` it names:

```html
<li role="none"><ul role="group" aria-labelledby="menu-file">
  <li role="none"><span class="dropdown-label" id="menu-file">file</span></li>
  <li role="none"><button type="button" class="dropdown-item">rename</button></li>
</ul></li>
```

A renderer that re-renders a dropdown in place gives the `summary` and each `.dropdown-label` its
own `id`. Without one, the runtime assigns a `dd-menu-*` id, and a patcher keyed on ids rebuilds the
summary and panel on every patch, so focus falls to `body`. The runtime re-asserts the roles, tabindex
and ARIA it owns if a patch strips them (`components.md`).

A select's trigger is named by its `<label>` through element reflection, so the runtime writes no id
on the page's label. In a browser without `ariaLabelledByElements` it falls back to writing
`dd-select-*-label`; a renderer that must support such a browser gives the label its own `id`.

**An invalid field names its error.** `aria-invalid="true"` never stands alone: the field points at
a `.field-error` through `aria-describedby`, and the error says what to write instead.

```html
<input id="repo" type="text" aria-invalid="true" aria-describedby="repo-err" />
<p class="field-error" id="repo-err">not an owner/repo — write it as poi/vu3</p>
```

**A table the engine enhances is `table[data-table-tools]`, and it should have a `data-table-id`.**
`initTableTools()` enhances every `table[data-table-tools]`; the id is optional there, but it keys the
view each reader's browser remembers (`table-view:<id>`), and without it the view is not kept. The pager
is stricter: `initTablePagination()` pages only a `table[data-table-id]` and leaves a table without one
alone. Choose a stable id.

**A tab row is an APG tab list.** `initTabs()` enhances `.tabs[role="tablist"]` whose `.tab`s are
`role="tab"` with `aria-controls` naming a `role="tabpanel"` (`data.md` has the full markup). A
renderer that re-renders the row writes the current `aria-selected`.

**Busy is `aria-busy="true"` plus `aria-disabled="true"`, never `disabled`.** The handler ignores a
press while busy; the spinner stays at full strength.

**A notice's role follows its tone.** `role="alert"` only for `data-tone="destructive"` and
`"warning"`; every other notice goes into a `role="status"` region already in the page.

**A glyph is coloured through its parent** (or `data-tone`), never by a colour on the glyph element.
Only the 51 words in `icons.md` exist; any other `data-icon` value draws an empty box.

**The theme menu's ✓ needs `initThemeSwitcher()`** (§1). A page that wires its own theme buttons calls
it anyway, or its menu shows no current theme.

**A ticker strip's `.tick-dot` is empty but for the state word.** The CSS draws ●, ✕ or ○ from the
row's `tick--*` class. A renderer that types the glyph into the cell shows two; it writes only
`<span class="visually-hidden">ok</span>` (`data.md`).

## 4. What changes with no markup change

- **`hidden` hides everything**, `!important`. A print stylesheet that reveals a `[hidden]` element
  no longer can: hide it with a class the page toggles instead.
- **Element defaults.** Bare `h1`–`h4`, `code`, `kbd`, `pre`, `mark`, `hr`, `blockquote` and `figure`
  take the house look; checkboxes and radios are restyled; text inputs and selects are 28px
  (`--control-h`) with a `--primary` focus edge.
- **`.card-terminal` pads 12px** (`--card-pad`; it was `0.85rem 1.1rem`). A card that must be flush is
  `.card-terminal--flush`, not a local `padding: 0`.
- **Only a card you can press answers the pointer.** A static card no longer warms its edge and glows
  on hover. An `a.card-terminal`, a `button.card-terminal` or a `.card-terminal--link` takes a
  `--primary` edge and a `--secondary` fill, and no glow. A page that relied on every card glowing
  makes the card a link, or accepts the still card.
- **Popups.** A chosen option or item shows a ✓ column, not a left edge and bold. `.select-panel`
  does not set `position`: `select.js` and `positionPopup()` place it.
- **The Tailwind entry is layered**: `base.css` in `@layer base`, every component file in
  `@layer components`, so a utility on the same element now wins. Utilities that lost before —
  border colours, a card's `p-*`, `outline-none` — now apply; remove the ones that were there only
  by accident. Every radius, bare `rounded` and `rounded-2xl` included, is 0.
- **`--content-pad` is 1.25rem below 40rem**, and a body with a `footer.status` reserves the
  footer's height itself: drop a page's own bottom padding for the footer.
- **`html.anim-off` also stops transitions**, and forced colours stops all of them.
- **A same-name local class merges, it does not override.** A page rule loaded after the bundle wins
  only on the properties it sets, so the system's other properties still reach the element. Rename
  the local class or adopt the system's. The new or newly reaching names a page is most likely to
  have already:
  - lists and badges: `.chip`, `.tag`, `.dot`, `.count`, `.state`, `.meta`, `.when`, `.thumb`,
    `.check`, and `ul.plain`, `ul.dash`, `ol.steps`, `td.actions`;
  - blocks: `.panel`, `.entry`, `.tree`, `.split`, `.console`, `.chart`, `.notice`, `.banner`,
    `.callout`, `.empty`, `.loading`, `.spinner`, `.dialog`, `.switch`, `.reveal`, `.clamp`, `.fence`,
    `.cmd`, `.cmd-text`;
  - text and layout: `.lede`, `.eyebrow`, `.markdown`, `.page-title`, `.section-head`, `.crumbs`,
    `.card-title`, `.card-head`, `.card-desc`, `.stat-tile`, `.layout`, `.content`, `.toc`.

  Measured: 0.59.0's `examples/style-guide.html` drew its colour swatches with a local `.chip` and
  `.meta`; on 0.60.0 the system's two rules reached them and collapsed each swatch to a 16px strip.
  That page is removed in 0.60.0; start a surface from `templates/page-chrome.html`.

## 5. A strict CSP (`style-src 'self'`)

- **The runtime writes no `style` attribute and injects no `<style>`.** It sets positions and sizes
  through the CSSOM (`element.style.top = …`, `style.cssText`), which `style-src 'self'` allows.
  `scripts/check-integration.mjs` fails a runtime module that calls `setAttribute("style", …)`,
  creates a `style` element or writes `<style` or ` style=` into markup.
- **`initSelects()` copies a select's own inline style onto its wrapper** through `style.cssText`,
  so a `<select>`'s own inline width reaches the control.
- **A colour chosen per element is an attribute, not a style**: `.tag[data-hue="<name>"]` for a
  tag's identity, `series[].hue` for a chart series (written as `data-hue`), `data-tone` for a state.
  The hue names are the twelve `--cat-*` names: red, orange, amber, lime, green, teal, cyan, blue,
  indigo, violet, purple, pink.
- **No documented markup carries a `style` attribute.** The templates and every code block in the
  skill are checked for one. A card, code block or meta line that needs a knob sets it from the
  page's stylesheet.
- **`templates/error-page.html`** has no inline style; its spacing is `.error-page` in `content.css`.
